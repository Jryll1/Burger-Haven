BURGER HAVEN FIXED — CHANGES AND TEST REPORT

- Preserved the existing FastAPI backend, SQLite database, menu, images, branding, customer accounts, checkout, payment choices, and order history.
- Customer storefront navigation no longer shows Staff Dashboard or Analytics. A defensive navigation filter removes stale/injected staff links, and page HTML uses no-cache headers to help prevent old navigation markup from sticking.
- My Orders / Order History loads automatically when a signed-in customer opens Account. It supports adding/removing order lines; editing quantities, product sizes, add-ons, soft drink brands/sizes; live subtotal and grand-total updates; Save Changes and Cancel; and a refreshable history.
- The backend checks order ownership, edit eligibility, product availability, quantities/options, authoritative prices, and optimistic concurrency. It uses a transaction, saves an edit audit record, updates the same order, and does not alter payment status.
- Staff operations and administrator analytics use separate permission checks. Staff-token access does not grant analytics API access when STAFF_TOKEN is configured. Analytics reads actual database values.
- Removed the manual Calculate Total and Calculate Scenario buttons; displayed totals and scenario calculations update automatically.

- Added real account roles (customer / staff / admin) enforced on the server for the staff dashboard APIs and the analytics API. Existing accounts migrate to customer; shared tokens keep working. Roles are granted only with manage_users.py. The /admin and /analytics pages offer account sign-in; customers get a clear no-access message; staff see an "Edited by customer" badge on edited orders.
- Fixed: two writes to an order inside the same second could leave updated_at unchanged and slip past the stale-edit check; every order write now produces a strictly newer version stamp.
- Fixed: a non-ASCII X-Admin-Token header caused a 500 error instead of 401.
