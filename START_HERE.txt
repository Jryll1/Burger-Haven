BURGER HAVEN FIXED — QUICK START (WINDOWS)

1. Extract this ZIP into a new folder; do not run it from inside the ZIP preview.
2. IMPORTANT: stop the older Burger Haven server window with Ctrl+C first. The screenshot previously provided was from the original project folder.
3. Double-click START_BURGER_HAVEN.bat in this Burger_Haven_Fixed folder.
4. Keep the opened terminal window running.
5. Open http://127.0.0.1:8000 in Chrome and press Ctrl+F5 once.

Storefront:       http://127.0.0.1:8000
Staff dashboard:  http://127.0.0.1:8000/admin
Admin analytics:  http://127.0.0.1:8000/analytics

The launcher starts FastAPI from Burger_Haven_App, uses Python 3.13, installs dependencies, and creates .env only if missing. The existing .env, SQLite database, uploads, payment options, and account data are included.

CUSTOMER ORDER EDITING
Log in to the account that placed the order and click Account. My Orders / Order History loads automatically. Click Edit Order beside an eligible order, update the items/options/quantities, and save. Totals update while editing and the existing order number is retained. Eligible unpaid orders are Pending Confirmation or Confirmed. Orders in preparation, completed/cancelled, paid, waiting for e-wallet verification, or placed as guests cannot be edited.

CUSTOMER NAVIGATION
The customer storefront does not include Staff Dashboard or Analytics. If those links still appear, the old server or old project folder is still being used: stop the old process, run this package's launcher, and press Ctrl+F5.

ACCESS
Staff: STAFF_TOKEN in Burger_Haven_App\.env. Admin analytics: ADMIN_TOKEN. A separate STAFF_TOKEN limits staff to operational tools; ADMIN_TOKEN permits analytics. Keep these values private.

STAFF / ADMIN ACCOUNTS (ROLES)
Every account has a role: customer (default), staff, or admin. Customers can shop, check out and manage My Orders. Staff can also open the staff dashboard (orders, payments, menu). Admins can do everything staff can plus open /analytics. The server enforces this on every request, so a customer who types /admin or /analytics, or calls the API directly, is refused.
1. The person registers normally on the storefront. Public registration can never create staff or admin accounts.
2. On the server, from the Burger_Haven_App folder, run:
     python manage_users.py list
     python manage_users.py set-role person@example.com staff
     python manage_users.py set-role owner@example.com admin
   (On Windows use the app's virtual environment, for example: .venv\Scripts\python manage_users.py list.) Changes apply on the person's next request; no restart is needed. Use "set-role EMAIL customer" to remove access.
3. They sign in on /admin (staff or admin) or /analytics (admin only) with their account email and password.
Existing accounts all stay customers until you promote them. The shared STAFF_TOKEN / ADMIN_TOKEN in .env still work exactly as before, so nothing you already use breaks. Keep tokens private and replace any example token before public hosting.
Note: the /admin and /analytics pages themselves still load for anyone as a sign-in screen; the data and actions behind them are protected by the server. Activity log entries still say "admin"/"customer" rather than the individual's name.
